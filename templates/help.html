Handover help

Use the guide for your role. Page-level help is available from the bottom-right button, and you can restart a tour on any page that offers one.

{% if user and user.role == 'reviewer' %}

Reviewer playbook

  1. Start with a project. Load a synthetic demo from Projects or create a project of your own. Add notes, task lists or chat exports and choose the most restrictive visibility level that is appropriate for each file.
  2. Check the evidence. Open Review, inspect the quoted source passage, and edit, reject or approve claims. Conflicts need a reason. Inferred claims cannot be approved as facts; Unknowns must be answered as testimony or rejected as irrelevant.
  3. Resolve handover gaps. Read Questions and Continuity Rehearsal. Answer critical questions and make sure at least one supported claim is approved. The app blocks sharing while review or readiness prerequisites remain.
  4. Publish carefully. On the project page, choose a sector and write a public summary that contains no confidential details. Only its title, sector and summary appear on the successor board.
  5. Review the team. Open Teams & requests, inspect the roster and the project request, then approve or decline with clear feedback. Approval shares the plan for the chosen expiry. You may instead create a demo team or directly assign a listed project.
  6. Follow through. Check the Share page for acknowledgement, “Unclear” questions and named action assignments. Revoke access if the handover should end early; use Activity to review recorded changes.
{% elif user and user.role == 'successor' %}

Successor team playbook

  1. Find relevant work. Open Incomplete projects. Search project names and summaries, or filter by Software, Healthcare, Banking & Finance, Cybersecurity, Education, General Operations or Community & Nonprofit.
  2. Request a project. Tell the reviewer what your team can contribute. A request is not approval: source files and plan details remain hidden while it is pending.
  3. Read the decision. Check My team for reviewer feedback, your roster and approved project assignments. If declined, use the feedback to decide whether to improve and request again.
  4. Use the plan safely. After approval, open the shared plan, review the approved items, acknowledge it, and assign actions to named roster members.
  5. Ask for help early. Mark actions done when completed. If an action is unclear, send it back with a specific note; the reviewer can reply on Share.
{% else %}

Reviewer quick start

  1. Load a demo or create a project and add files.
  2. Review source-backed claims, resolve conflicts and Unknowns, then pass the readiness gate.
  3. Publish a safe summary, review a successor-team request, and share only the reviewed plan.

Successor quick start

  1. Search or filter the incomplete-project board and request a project.
  2. Wait for reviewer approval and read feedback in My team.
  3. Use the approved plan, assign tasks and send unclear actions back with a note.

More features

Timeline
On a shared plan, “See it as a timeline” orders dated approved claims. Restricted or unapproved facts are not shown to successors.
Questions and dark matter
Review’s Questions page collects missing information, repeated unexplained terms, recurring risks, and areas with concentrated ownership.
History and undo
Open History under a claim to review changes. Undo and redo are available to reviewers; a new change clears the redo path.
Replacing a file
Upload a file with the same name to replace it. Claims whose evidence no longer matches are sent back for review, and visibility cannot be lowered by re-uploading.
Readiness rehearsal
Estimates whether a successor’s likely questions can be answered from the approved claims they are allowed to see. Critical unresolved questions block sharing.
Downloads
Download Excel, Word, CSV, XML or JSON, or use Print to save a PDF. Exports contain only claims permitted for the current recipient.
Notifications and activity
The bell lists relevant updates. Reviewers can open Activity to see recorded actions.
Restart a tour
Open Help & tour from a page and choose Tour this page. “Not now” on first sign-in asks again on a future sign-in; “Don’t ask again” stores that choice for this account.

Common questions

Why can I not approve a claim?

Inferred guesses cannot be approved as facts. Edit them so the evidence matches, or reject them. Unknown claims need testimony or rejection; conflicting claims need a reason.

Why can I not share or approve a project request?

All claims need a decision, at least one supported claim must be approved, and critical rehearsal questions must be answered. Follow the blocker links on the Share page, then try again.

Why can’t successors see the source files?

Successors see only approved claims within their access level, after the reviewer approves a request or assigns a project. The public board contains only the reviewer-written title, sector and summary.

Where does the data go?

Project data is stored in the app’s SQLite database. The optional AI helper is off unless configured; if enabled, source text may be sent to its configured provider. Do not use this demo for real patient, customer, financial-account or live security-incident data.
